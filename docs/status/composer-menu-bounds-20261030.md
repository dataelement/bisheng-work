## 根因与实现

`MenuView` 原先调用通用高度 hook，以窗口顶部固定 `84px` 为上边界、`400px` 为设计高度。Work 菜单实际位于会话滚动容器内，容器起点还受到桌面标题栏、模式栏和会话布局影响。菜单上部因此可能落在滚动容器的裁切区域；菜单内部滚动只改变列表内容，容器仍裁切菜单顶部。字体放大、显示缩放、窗口变小和输入框增高会压缩可用空间。

菜单组件现在读取自身定位锚点和各级滚动/裁切祖先的可见交集，以实际行高调整设计高度，保留边缘间距。常规情况下菜单继续位于输入框上方；空间较小时，菜单在当前内容区内向下展开，提供可滚动的完整菜单行。菜单行按实际文字高度布局，列表负责内容滚动，输入框草稿保持原值。ResizeObserver 观察布局祖先、菜单、菜单行和面包屑，窗口和滚动事件同步重算，关闭时释放观察器和监听。

修改直接落在 Harness 菜单组件的布局逻辑，沿用仓库已有依赖重放机制分发。兼容版本为 `@deepseek-ai/dsh-client-ui-input-trigger@0.2.1-rc.2`；上游菜单具备相同裁切边界和动态布局能力后，可移除此段并保留行为回归。

## Windows 验收步骤

1. 安装包含本修复的 Windows 包，打开工作模式的新会话，点击「＋」。
2. 分别设置系统显示比例 100%、125%、150%、200%，并切换应用字体大小；滚动到列表首尾，确认顶部标题、第一项和最后一项完整可见且可点击。
3. 打开已有会话，重复上述操作；保持菜单打开，调整窗口大小和输入框高度。
4. 使用方向键在首尾循环，确认选择项可见、草稿保留；关闭并重开菜单，确认定位正常。
