## 根因与行为

企业客户端通用请求成功后会发出 `dsh-desktop:enterprise-account-changed`，包括普通账号信息读取。左侧列表收到通知即清空 `items`、分页状态并使当前请求失效，随后重新读取账号及会话。重复通知还会触发重复拉取，多页列表在清空后只重载第一页。

列表现在先获取主进程状态，通过主进程 epoch 判定数据归属。同一身份的刷新保留已加载页及行；已有请求由当前任务完成，所有所需页成功返回后一次性替换。请求失败保留旧内容与重试入口，成功空响应替换旧列表。加载中的首次空白状态与已经确认的空列表分别显示；后台刷新保持行与空态稳定。

轮询和宿主订阅共用状态应用流程，身份变化或退出登录时原子清理账号数据及分页，并使旧请求失效。缓存保存在当前 renderer 的导航服务内，生命周期和原有插件一致。服务端接口、主进程凭证和 Harness 本地 Work 会话列表沿用原有链路。
