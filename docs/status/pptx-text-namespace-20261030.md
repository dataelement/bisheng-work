# 三页 PPTX 模板导入失败修复

## 反馈与基线

用户反馈：Windows x64、BISHENG 1.2.0-test4，导入三页模板及重新选择文件均报 `Imported paragraph serialization failed`。原文件在 PowerPoint 16.0.20527.20088 可以打开。

本次按用户指定的 `dataelement/bisheng-desktop:V1.2.0` 修复，起点 `e928c8c3bd5d2f188f17b7d93e0fbd7bc13eaf90`，分支 `codex/v120-pptx-text-namespace`，独立工作树 `bisheng-work-v120-pptx-text-namespace`。安装的 Harness 为 `0.2.1-rc.2`，Electron 为 `43.0.0`，使用该版本的锁文件。

原附件 `模板验收120.pptx`：54,521 字节，SHA-256 `1f26a5a10719ef36a2294ab2327dfe8ce4c70b323000f2a7696679f29239a014`。附件保存在本地调查证据中，仓库使用合成样本做回归。

## 根因与历史范围

原附件的 DrawingML 命名空间声明位于文字节点附近。导入器合并母版、版式和本页的 `bodyPr`、`pPr`、`rPr` 时，原代码通过 `setAttribute(attr.name, attr.value)` 复制属性，把 XMLNS 声明当作普通属性。序列化器随后基于元素的命名空间自动补充声明，形成同一节点上重复的 `xmlns:a`。原文件转换后的 12 份原生文字片段均出现此问题；模板准备进入重新导出预览阶段时，段落校验抛出反馈中的错误。

历史修复 `a23788a` 已覆盖空前缀声明，`26632e7`（#718）处理 Windows 字体与字重。此次出错的属性合并来自 `0cb0008`（#683），上述修改后仍使用原复制逻辑。此次为合法局部声明的继承与序列化问题。

合并现在根据属性命名空间复制语义属性，局部声明由合并后节点的命名空间身份生成。现有母版/版式/本页样式优先级保持；段落有效性校验继续执行。标准 `a` 和等价 `drawing` 前缀均纳入覆盖。

## 验证

- 修复前：新增标准前缀回归复现重复 `xmlns:a`；原附件在生产转换/导出链路复现反馈中的异常。
- 修复后：命名空间、版式保真、模板示例三个文件共 40 项通过。新增两项覆盖三页、局部声明、不同前缀、粗体与字号、所有导出 XML 解析、重新导入与重选。
- 干净依赖安装、类型检查、生产构建、差异检查通过。
- macOS arm64 使用重新构建的生产 PPT 插件、隔离存储、宿主认证入口与审计链路导入原附件。首次准备、取消后重选、两轮各三页完整预览、进度完成及保存模板均通过。预览由真实 LibreOffice/PDFium 生成，全部为 1920×1080；第 2 页预览已目视检查。第一轮准备约 4.9 秒，重选约 3.3 秒。
- 完整串行回归 `npm test -- --maxWorkers=1` 通过：321 个文件、3,181 项通过；4 个文件、5 项按环境条件跳过。耗时约 502 秒。

本机缺少 SimSun，预览诊断正常报告字体替代。上述证据确认导入与序列化流程；Windows 更新后安装包、原机字体环境、PowerPoint 编辑保存重开和用户验收待执行。

本地证据：修复工作树 `artifacts/pptx-text-namespace/`，包含修复前/后测试、构建日志、原附件验证脚本、两轮预览与 `original-result.json`。
