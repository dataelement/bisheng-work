# DSH 直接连接 BiSheng

V1.2.0 已合入 main 的原生毕昇认证。企业连接的创建授权、换证与刷新、退出使用 `/api/v1/dsh/authorizations`、`/api/v1/dsh/token`、`/api/v1/dsh/logout`，直接请求 Python BiSheng，可以不部署 Java Gateway。服务端仍可提供旧 `/api/dsh/*` 别名。

客户端校验协议白名单 0.4.0 与 0.5.0、PKCE、state、同源浏览器确认和回调响应。凭证保存在既有安全存储中。模型审计正文、message_sources、父子会话和标题能力协商保留。旧席位错误只作为连接旧服务的兼容提示，使用重新登录或升级平台的文案，不引导购买或分配席位。

## 兼容范围

- 服务端切换到 Python 认证后应重新登录，旧 Gateway Token 不导入新会话。登录切换不清理本地聊天历史。
- 当前客户端固定使用 v1 认证路径，没有旧路径回退。仅提供 `/api/dsh/*` 认证的旧服务端不能直接兼容；协议版本白名单不代表认证端点兼容。
- 旧客户端连接新服务端可使用 Python 的旧路径别名；实际旧安装包的登录、刷新和退出仍需按版本组合验收。
- 新旧客户端分别使用独立测试 Profile；HTTP 协议兼容不等于客户端持久化格式可无损降级。
