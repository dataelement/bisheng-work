# DSH 敏感词控制：功能说明与 QA 测试指引

更新：2026-10-24。适用范围：F111，客户端 `feat/bisheng-work-dsh-guardrails` 合入 `V1.2.0` 的 PR，以及配套 BiSheng / Gateway 的 work120 版本。

配套记录：[客户端 V1.2.0 合并验证](./dsh-sensitive-word-control-validation.md)。

本说明用于提测。文中的“预期”是 QA 验收要求；“已验证”仅代表明确列出的开发验证，不代表完整功能验收完成。

## 1. 功能说明

管理员在平台“客户端 → 敏感词控制”中，为所选租户统一配置输入和输出检查。该租户使用不同 DSH 模型时遵循同一套规则，不按用户、部门或模型分别配置。

- 支持启停、检查输入、检查输出、内置词库、自定义敏感词和阻断提示。首次使用默认关闭。
- 使用字面匹配，区分大小写；不包含同音词、拼音、语义识别、图片 OCR、音视频或加密推理检查。
- Gateway 根据 backend 验证后的当前用户／租户选择策略；客户端传入的租户字段不能决定使用哪套规则。
- backend 继续负责当前会话、模型权限、额度和实际用量；身份缓存不能替代这些准入检查。
- 输入命中时不调用模型。输出命中时终止向客户端交付，但模型可能已执行，实际用量仍应结算。
- 流式回复已经显示的安全前缀可以保留；不能继续显示完整命中词，也不能把被拦截的一轮显示为正常成功。
- 工具参数须完成检查才可执行；被拦截、参数不完整或取消时不能继续调度该轮工具。
- 拦截结果会回传审计，可在请求详情、会话命中汇总和筛选中查看；内容安全事件不保存原始命中词、模型正文或凭据。

保护对象为 DSH Work 原生模型转发的 Chat Completions 和 Responses，各含流式／非流式。V1.2.0 内嵌的企业 Chat、普通应用、知识选择、企业技能／工具是相邻回归范围，不能仅因为入口也叫“Chat”就认为它使用同一套 DSH 策略。

## 3. 建议的测试数据

仅选择自定义词来源，使用合成词 `F111_QA_BLOCK_20261024`，阻断提示设置为 `本次测试内容已被拦截，请调整后重试。`。先用无命中词的输入与回复验证正常通路，再进行负例。内置词库用例单独执行。

输出及工具测试不能依赖真实模型“恰好生成”敏感词：由测试负责人预置受控 Provider 场景，保证回复、分片、工具名／参数、用量确定。控制面仅测试机 loopback 经授权隧道可用，不对外开放，也不把控制密钥交给模型。

| 场景 | Provider / 客户端准备 | 应观察到的事实 |
| --- | --- | --- |
| 正常回复 | 确定安全文本；合成用量 input=30、output=50、total=80 | 文本和终态正常；一条模型请求按实际 80 结算 |
| 输入拦截 | 用户输入含合成敏感词；Provider 场景计数初始为 0 | 模型物理调用增量 0，额度不增加 |
| 输出拦截 | Provider 输出含合成敏感词；输入本身无命中 | 不交付完整命中词；模型执行与安全结果分别记录 |
| 分片拦截 | 敏感词跨相邻输出片段、UTF-8 传输片段；Responses 的 delta/done/final 单独设置 | 不因分片或最终新增文本漏检 |
| 工具正例 | Provider 发出实际已注册的 `read`，参数指向临时文件；文件首行含新的随机标记 | 一次成功工具调用；结果含该随机标记，而非“未知工具”或权限错误 |
| 工具负例 | 只在工具参数中放入敏感词，输入和其他文本安全 | 当前轮 `tool/call`、`tool/result` 均为 0，无文件读取 |

测试 Provider 支持 `tool_name=read` 和可选 `after_tool_text`，收到关联的工具结果后才返回最终安全文本，避免反复发出工具调用。Provider 的 HTTP 成功计数不能证明真实工具执行成功；必须另查实际客户端成功结果与文件随机标记。更换测试场景使用新的场景 ID，不复用开发验收场景。

## 4. P0：功能验收清单

以下正常／输入拦截／输出拦截至少覆盖 Chat、Responses 两个模型。流式通过客户端验证；非流式通过正式认证的 API 测试补齐，不能把同一个流式 UI 用例重复计为四种协议模式。

| 用例 | 操作步骤 | 预期结果 |
| --- | --- | --- |
| QA-01 默认关闭 | 管理员读取原策略；关闭检查；普通用户发送安全输入，并使用受控敏感输出 | DSH 请求保持原透传行为；新审计标“已关闭”，不是“通过”；历史命中仍保留 |
| QA-02 正常请求 | 开启输入／输出检查，保存；等待页面公布的生效窗口，再发送确定安全请求 | 两方向通过；文本、工具和用量语义正常；没有多发一次模型请求 |
| QA-03 输入命中 | 新会话输入包含测试词 | 立即显示租户阻断提示；不显示正常完成；不调用 Provider、不新增用量；有独立输入命中记录 |
| QA-04 输出命中 | 输入无命中；受控 Provider 返回命中词 | 非流式不交付危险正文；流式停止交付，不显示完整命中词；不得正常成功结束或自动重试 |
| QA-05 分方向 | 分别只开输入、只开输出，再执行对应正负例 | 只对已开启方向检查；关闭方向显示“已关闭”，未进入输出阶段可显示“不适用” |
| QA-06 工具正例 | 选择确定的 `read` 场景，读取临时文件 | 一次 `read` 调用与一次成功结果，结果包含文件的新随机标记，随后安全结束 |
| QA-07 工具参数命中 | 同一协议新会话，敏感词仅出现在工具参数 | 客户端显示拦截，当前轮无工具调用／结果；不能仅凭工具卡片没有显示就判断零执行 |
| QA-08 提示与语言 | 配置租户提示；分别切换客户端支持的中文、英文、日文后触发阻断 | 租户自定义提示原样显示；系统固定提示按当前语言；新会话不能沿用上一会话语言；隐藏的语言入口记待验，不改客户开关造通过 |
| QA-09 审计命中 | 在平台“客户端 → 审计”定位本次会话，展开请求 | 总体／输入／输出检查结果正确；会话命中数按请求去重，多条事件不能把同一请求计多次 |
| QA-10 审计筛选 | 高级筛选分别选择“命中”“输入命中”“输出命中”；再叠加本次完整会话 ID／请求 ID | 只显示匹配记录；空结果有正常空态；清空筛选后恢复，不丢原记录 |
| QA-11 审计详情 | 打开输出拦截记录的检查详情与模型用量 | 可看规则 ID、策略版本、事件时间、Gateway／Backend 请求编号；可先看到拦截决定，再看到后续读取结果；模型实际成功／实际用量可与安全“命中”并存 |
| QA-12 普通用户权限 | 普通平台身份尝试读写策略；回到管理员读回原配置 | 普通用户精确拒绝，配置未变；原生 DSH 登录或 profile 成功不赋予管理员权限 |
| QA-13 非法配置 | 无有效词开启方向、提示为空、提示超过 2048 字符等；随后重新读取 | 拒绝保存并明确原因；原版本／配置保持不变，不能显示已启用但无有效规则 |
| QA-14 并发编辑 | 两个管理员窗口读取相同版本，A 保存后 B 保存旧版本 | B 得到明确冲突并刷新处理，不能静默覆盖 A；最终 GET 保持唯一已提交版本 |
| QA-15 身份与额度 | 正常调用后撤销该测试会话／模型授权或耗尽其测试额度，再请求 | 原有 backend 准入继续拒绝；不因 profile 缓存放行；不自动重试模型；不用敏感词提示掩盖账号／额度错误 |
| QA-16 关闭与恢复 | 留存命中记录；关闭策略后再开新请求；最终恢复测试前设置 | 关闭后新请求不检查，历史命中仍可查；正在处理的请求使用其开始时快照；最后 GET 确认恢复 |

策略保存成功后，新请求最多 5 秒内使用新策略。等待 5 秒后观察生效只是功能检查，不等于已测得精确传播延迟，也不能替代多副本验收。

## 5. 审计与用量判定

| 检查结果 | 含义 | 不应误判为 |
| --- | --- | --- |
| 通过 | 已启用方向完成检查且无命中 | 模型一定成功或一定产生费用 |
| 命中 | 发现敏感词 | 模型一定没执行、用量一定为 0 |
| 检查失败 | 必须检查但设施／解析失败 | “命中”或“安全通过” |
| 已关闭 | 对应检查未启用 | 已完成内容检查 |
| 不适用 | 对应阶段没有发生，例如输入命中后未进入输出 | 输出已通过 |
| 未收到完整结果 | 暂无完整检查事实 | 安全无命中 |

- 输入拦截：独立安全记录；模型执行、模型结果及结算为不适用。不能制造一条模型执行成功且 0 Token 的记录。
- 输出拦截：已执行模型仍按真实 Provider 用量结算。受控用例应为 30/50/80，不因客户端停止展示改成 0。供应商用量未知时保持未知，不补成 0。
- 内容安全详情只展示规则引用和必要元数据，不展示原始命中词、完整模型正文、Token、HMAC 或 License。
- 网关生成的公开错误编号可能与 Backend 模型审计编号不同，应通过详情的关联字段确认，不要求两个编号相等，也不能用 profile 请求编号代替。
- 同一会话可能还有标题、压缩、历史等辅助模型请求。判断“不自动重试”请按本轮模型请求及用途统计，不直接把会话总请求数当重试或工具次数。
- 审计异步更新；在合理期限内刷新请求详情。列表暂未收到完整结果不能马上定为丢事件；长期不收敛应记录缺陷，不能无限等待后标通过。

## 6. P1：异常、兼容及专项测试

| 专项 | 重点预期 | 所需条件 |
| --- | --- | --- |
| 历史／内部请求 | 历史消息、自动标题、压缩等不因用途声明跳过检查；不同消息不能错误拼接成词 | 可控 Provider 与精确请求用途 |
| Responses 特殊观察 | delta/done/final 新文本、可读 reasoning content/summary、相邻空 part、工具 JSON、Unicode 均正确 | 四模式自动化场景 |
| 请求边界 | 非法 JSON、重复字段、未知输入结构及精确 32MiB+1 在转发前拒绝 | 正式 DSH 凭据及边界脚本；不能打印大正文 |
| 请求解析拒绝审计 | 上述预转发请求返回 `400 invalid_request`、无 Backend 请求头／模型调用／账本变化；发生在安全记录器之前的拒绝不要求虚构 ERROR 事件 | 两轮完整精确查询和 Provider 全局计数 |
| 检查设施故障 | profile／策略／Redis／词库不可用时不冒“关闭”透传；按阶段返回检查不可用 | 独立隔离故障环境，勿停当前共享测试服务 |
| 缓存与准入 | profile 最长 30 秒且不续期；不同完整 Token／backend 不串缓存；缓存不绕过当前会话、模型权或额度 | 多身份与可观测调用计数；多副本另验 |
| 审计可靠性 | 重启、重复投递、乱序、丢 ACK、原生事实先后到达不丢命中、不重复主行／用量 | 独立实例及故障控制权限 |
| 原有功能 | V1.2.0 的企业 Chat／Work 切换、企业登录、模型目录、知识选择、技能和工具选择、取消、主题、菜单仍可用 | 本 PR 实际客户端构建及相应授权资源 |
| 旧敏感词功能 | 普通应用原有敏感词、路由和旧响应保持原行为；不被 DSH 租户策略误接管 | 原应用专用测试 fixture |
| 无 Gateway | 本地登录、模型权与计量照常工作 | 单独不带 Gateway 的隔离部署 |
| 公开入口封闭 | 受保护部署不能从客户端可达地址绕过 Gateway 直连模型入口 | 实际客户端网络／代理拓扑 |
| 双库／容量 | MySQL 与 Linux DM8 行为一致；大数据筛选、树／会话聚合、并发和堆负载达标 | 专用数据库、数据规模和资源配额；小表／mock 不能代替 |
| 原生平台 | Windows、macOS 安装包与实际工具屏障、取消及 UI 行为 | 对应原生环境，不用 macOS 单测替代 Windows 安装验收 |

## 8. 缺陷提交与测试收尾

缺陷至少记录：客户端提交／平台和 Gateway 构建、UTC 时间、租户和测试角色、当前模型及协议、是否流式、策略版本和开启方向、会话／请求编号、复现步骤、期望与实际、脱敏截图。工具问题补本轮调用／成功结果次数；用量问题补输入／输出／总量及结算状态。禁止附带密码、原始 Token、完整请求头或原始敏感正文。

测试结束后由当前配置负责人恢复测试前策略并 GET 确认；若版本已被别人修改，应停止自动覆盖并协调恢复。只清理本轮创建且能确认归属的文件、账号、模型与场景；保留审计证据，不批量清空用量、历史记录或未确认投递事件。不要改动 109 的其他部署环境。
