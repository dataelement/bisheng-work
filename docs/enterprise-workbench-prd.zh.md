# 企业工作台目录 PRD

版本：2026-10-15

范围：bisheng 企业版 Desktop
状态：待评审。服务端列表、详情和原包下载按联调契约开发，接口尚未部署；联调前以实际响应复核路径和字段。

本文覆盖本租户工作台的目录、详情、原包完整性核对和直接安装。企业工作台与公开市场工作台不是同一类：企业包核对通过后可以直接装进本机，不走公开市场的 `market-install`，也不使用插件发布快照。`allow_third_party_workbenches === false` 时，工作台市场改为展示企业上传的目录，企业包仍可安装。

本文所称「核对原包」只验证文件，核对结束后删除，不把文件交给用户。安装是另一次下载：主进程核对通过后保留临时包，交给本机 generation 安装，安装结束再删除临时包。

与 [企业版三方插件市场与工作台能力 PRD](enterprise-third-party-capability-prd.zh.md) 的关系：该文里「关闭三方工作台市场时没有企业网络目录、列表只剩本地工作台」由本文取代。该文对公开市场安装、本机开发安装、已安装内容保留和插件市场的约束继续有效。

## 1. 背景

企业插件已经有独立目录。企业登录有效时，设置里的「来自企业」读取当前租户插件，不随 `allow_third_party_plugins` 隐藏。请求经主进程 Broker 发出，渲染进程不持有 access token。

工作台还没有对应目录。`allow_third_party_workbenches === false` 时，`packages/dsh-desktop-workbenches/client.js` 把 `networkMarket` 置为关闭，隐藏「工作台市场」和「我的收藏」，只留下「已安装」和本机开发安装。公开 catalog 与 `POST /api/desktop-workbenches/market-install` 被拒绝。结果是管理员在企业侧上传的工作台没有展示入口。

服务端约定新增三个接口：本租户目录、当前版本详情、当前版本原始 `.tgz`。`allow_third_party_workbenches` 只约束第三方来源的新增安装，不阻止这三个接口。现有插件 `/sync` 发布快照不覆盖工作台。三个接口的成功响应不表示允许安装。

## 2. 目标

1. 企业登录有效且用户已开启工作台时，无论三方工作台市场开或关，都能看到当前租户已上传、且有可用版本的工作台。这是本文确定的产品规则，不由 `allow_third_party_workbenches` 控制。
2. 三方工作台市场关闭时，「工作台市场」页展示这份企业目录，不再变成空白的纯本地列表。
3. 三方工作台市场打开时，公开市场保持原样；企业目录以独立来源展示，不并进公开 catalog 的安装、更新、收藏和投稿。
4. 列表、详情和原包下载走与企业插件相同的凭据边界：DSH access token、同一 BiSheng 地址、Broker 转发、账号或租户切换后丢弃旧数据。
5. 客户端能按详情中的长度和 SHA-256 核对原始包。核对通过表示取得管理员上传的原包。
6. 企业工作台可以直接安装。安装使用核对后的本地 `.tgz`，调用 Plugin Manager 的 `installBundle` 并校验企业包名、版本，不经过 `allow_third_party_workbenches`。
7. 本机已安装工作台、本机开发安装、公开市场安装拦截和已有用户数据保持现有行为。

### 2.1 交付优先级

- **P0：企业目录可见。** 完成列表、详情、租户隔离、失败重试，以及三方市场关闭时以企业目录替代公开市场。服务端列表和详情接口可联调后交付。
- **P1：原包完整性核对。** 用户在详情中主动触发临时下载，客户端核对长度、SHA-256 和 ETag；不保存、不安装。制品接口、最大包体和超时约束确认后交付。
- **安装。** 核对通过的企业包直接安装到本机 generation。不包含插件发布快照、自动更新和卸载协议。

P0 不依赖 P1。制品接口未部署或 P1 尚未交付时，企业目录和详情仍可上线，但不显示「核对原包」操作。

## 3. 非目标

- 不把企业工作台装入插件 `/sync`，不复用插件离线包、发布快照、generation 或「来自企业」的安装、启用、停用、卸载。
- 不调用 `POST /api/desktop-workbenches/market-install`，不写入 `market-installs.json`。企业安装使用独立的 `enterprise-install`，来源是 `enterprise`，不复用公开市场身份。
- 不把核对后的字节交给「安装本地工作台」，也不把临时路径交给渲染进程。本地安装仍只接受用户在本机选择的目录。
- 不根据 `package_metadata`、`verification_level` 或三个接口的成功响应判断宿主依赖可解析、工作台可运行或允许安装。
- 不在开关变为关闭时卸载、停用或删除已经安装的工作台、会话、笔记和收藏。
- 不使用管理员 Web 凭证、refresh token、MinIO 地址或 `/admin/*`。
- 不改变官方 DSH 安装包的社区市场策略。

企业工作台可以直接安装。安装不依赖插件发布快照，也不受 `allow_third_party_workbenches` 限制。核对原包仍然只验证并删除文件，不作为安装的前半段。

## 4. 名词

| 名词 | 含义 |
| --- | --- |
| 企业工作台 | 当前登录租户经企业目录下发、且有当前版本的工作台。入口在工作台市场，不是公开 Awesome 目录 |
| 公开工作台 / 第三方工作台 | 现有网络工作台市场中的条目。身份是 `owner/repo`，安装走 `market-install` |
| 本地工作台 | 用户在本机开发并安装的工作台，以及本机已经安装的工作台。含以前从公开市场装上、开关关闭后仍保留的项 |
| 工作台功能 | 用户在设置里打开后，左侧出现「工作台」。这是本机偏好，不是服务端开关 |
| 三方工作台市场 | `allow_third_party_workbenches`。只约束公开市场及其他远程来源的新增安装 |

身份规则沿用服务端契约：

| `identity_kind` | `workbench_key` | `legacy_id` | 客户端 |
| --- | --- | --- | --- |
| `repository` | 非空 `owner/repo` | `null` | 按仓库身份展示。这是新规范身份 |
| `legacy` | `null` | 非空旧 ID | 可展示，详情中可核对原包。标记为旧格式。不把它显示成仓库，也不推断它可以安装 |

`id` 与 `current_version.id` 只用于 API 定位，都是 32 位十六进制。版本字符串是完整 SemVer，可含预发布段。不用版本号代替版本 ID，不用 `legacy_id` 或 `workbench_key` 拼 API 路径。

## 5. 目录能力引入前后的差异（历史背景）

引入本文目录能力前，关闭三方工作台市场时：

- `enterpriseCapability.allowThirdPartyWorkbenches === false` 后，市场只保留「已安装」。
- `refreshCatalog()` 清空 `remoteCatalog`，不请求 `/api/desktop-workbenches/catalog`。
- 设置文案写明这里只显示已安装和本机开发的工作台。
- `parseMarketRequest` 只放行 `capabilities`、`catalog`、`sync` 和插件制品路径。工作台三个新路径会被 Broker 拒绝。

本文之后：

- 关闭三方市场时仍请求本租户工作台目录，并显示在「工作台市场」。
- 公开 catalog、`market-install` 和投稿到公开仓库继续按开关拒绝。
- Broker 白名单增加工作台列表、详情和制品三条路径。制品字节留在持有凭据的一侧，不进渲染进程。

## 6. 服务端契约

身份与企业插件相同。使用现有登录取得的 DSH access token，请求同一个 BiSheng 公开地址：

```http
Authorization: Bearer <DSH access token>
```

| 方法与路径 | 用途 | 成功响应 |
| --- | --- | --- |
| `GET /api/v1/dsh/market/workbenches?page=1&size=20` | 本租户有可用版本的工作台目录 | JSON 信封 |
| `GET /api/v1/dsh/market/workbenches/{id}` | 当前版本详情 | JSON 信封 |
| `GET /api/v1/dsh/market/workbenches/{id}/versions/{version_id}/artifact` | 当前版本原始 `.tgz` | 二进制，无 JSON 信封 |
| `GET /api/v1/dsh/market/capabilities` | 既有安装开关 | 已实现。本文只继续读取 `allow_third_party_workbenches`，不新增字段 |

约定：

- 不传 `tenant_id`、`user_id` 或 `X-DSH-Market-Tenant`。租户由已验证身份决定。
- 渲染进程不直连 BiSheng，不持有 access token。主进程 Broker 转发，与企业插件的 `/v1/market` 相同。
- 列表和详情先确认 HTTP 成功，再确认 `status_code === 200`，再校验字段类型。响应头 `Cache-Control: no-store`。
- 分页从 `page=1` 开始。`size` 只发送 1–100，默认 20。
- 登录、账号、租户或 BiSheng 地址变化后，丢弃旧列表、详情和已下载字节，并重新请求。不跨用户或租户复用缓存。
- 拟新增业务码 `26207`（工作台或当前版本不存在）、`26208`（制品缺失或校验失败）、`26206`（并发状态冲突）尚未落地。客户端按 HTTP 状态、统一信封和通用失败路径处理，不以这三个码作为唯一判定。二进制成功响应不解析 `status_code`；错误响应才按 JSON 处理。

`allow_third_party_workbenches === false`、字段缺失或 capabilities 读取失败，都不跳过企业工作台目录。该字段仍只拒绝公开市场和其他远程来源的新增安装。

### 6.1 列表

`data.data` 是数组，`data.total` 是本租户符合条件的总数。空目录是 `[]` 和 `0`。列表只有当前版本摘要，没有原始包地址和历史版本。

展示名用 `display_name`。`package_name` 是 npm 包名。`id` 是服务端生成的 32 位十六进制标识。

列表条目至少要能识别身份才进入展示：

| 字段 | 要求 |
| --- | --- |
| `id` | 32 位小写十六进制 |
| `identity_kind` | `repository` 或 `legacy`，并满足第 4 节的身份组合 |
| `package_name`、`display_name` | 非空字符串 |
| `current_version.id` | 32 位小写十六进制 |
| `current_version.version` | 非空字符串 |

`description`、`verification_level`、`updated_at` 缺失或类型不对时，该字段留空，不丢弃整条。单条身份或当前版本不合法时跳过该条并保留诊断，其余合法条目仍展示。信封不合法、`status_code !== 200`、`data` 缺失、`total` 不是非负整数，则整页失败，不把失败显示成空目录。

客户端按页拉取，以服务端每页返回的**原始条目数**累计进度，不能用过滤后的合法条目数判断是否达到 `total`。累计原始条目数达到 `total`，或服务端返回空页时停止。最多 100 页；页数用尽仍未达到 `total` 时，整次读取失败，不把残缺结果当成完整目录。被跳过的非法条目数量只写入诊断，不改变下一页页码。

### 6.2 详情

详情保留列表字段，并把 `current_version` 扩展为 `id`、`version`、`sha256`、`size_bytes`、`artifact_url`。可进入核对的详情必须同时满足：

- `sha256` 为 64 位小写十六进制。
- `size_bytes` 为正安全整数，且不超过客户端 512 MiB 的企业工作台核对上限。
- `artifact_url` 是当前 BiSheng 地址上的路径 `/api/v1/dsh/market/workbenches/{id}/versions/{version_id}/artifact`，且其中的两个 ID 与详情一致。

其他域名、查询串、由 `package_name`、`workbench_key` 或版本号拼出的地址都拒绝。`package_metadata` 各字段可选；类型不对的字段忽略，不影响其余字段展示。`verification_level` 为 `static` 时只作诊断，不显示成可安装或可运行。

512 MiB 是 Desktop 的本地防护上限，不代表服务端允许上传同等大小。服务端实际限制更小时以服务端为准；后续调整该上限须同时评估磁盘、超时和 Windows 文件占用。

`package_metadata` 可展示的字段：`repository_url`、`patch_entry_id`、`server_entry`、`client_entry`、`bundle_patch`、`license`、`node_engine`、`dependencies`、`legacy_manifest`。入口路径只供查看，不作为加载路径。

## 7. 能力矩阵

用户是否打开工作台，只影响左侧入口和是否进入工作台界面。企业目录在登录有效且工作台功能已开启时读取。

| 三方工作台市场 | 工作台市场页 | 企业目录 | 公开市场安装 | 本机开发安装 | 已安装工作台 |
| --- | --- | --- | --- | --- | --- |
| 开 | 公开市场，另有「来自企业」 | 展示，可直接安装 | 允许 | 允许 | 可打开、停用、卸载 |
| 关 | 企业目录，页签仍叫「工作台市场」 | 展示，可直接安装 | 拒绝 | 允许 | 可打开、停用、卸载；不能从公开市场更新 |

「来自企业」插件页不受本表影响。未登录、会话过期或切换租户完成前，不展示企业目录，也不沿用上一份列表。

## 8. 信息架构

工作台功能的开关、左侧入口和设置页签位置不变，仍由现有三方能力 PRD 规定。本文只改工作台市场内部的数据来源。

用户已开启工作台且企业登录有效：

- `allow_third_party_workbenches === true`：保留「工作台市场」「我的收藏」「已安装」。增加「来自企业」。公开卡片继续提供安装、更新、收藏和投稿。企业卡片不出现在公开列表、收藏或 `market-install` 的身份空间里。
- `allow_third_party_workbenches === false`：显示「工作台市场」和「已安装」，不显示「我的收藏」。此时「工作台市场」的数据是企业目录。不请求公开 catalog。保留「安装本地工作台」和「制作我的工作台」的本机开发路径，不提供向公开仓库投稿。

数据不合并：

- 「工作台市场」或「来自企业」只展示服务端企业目录，不推断本机是否已安装，也不提供运行开关。
- 「已安装」只展示本机清单和已加载 provider，不用企业 `id`、`workbench_key` 或 `package_name` 自动关联企业卡片。
- 即使同一工作台同时出现在企业目录和本机清单，也显示为两个来源明确的条目；待安装协议确定后再定义关联规则。

企业卡片展示 `display_name`、`description`、`package_name`、当前版本号和身份。仓库身份显示 `workbench_key` 文本。旧身份显示「旧格式」和 `legacy_id`。提供安装和「核对原包」，不提供收藏，也不把企业条目并进公开市场的更新。详情可查看 `package_metadata` 和第 6.2 节的版本字段。安装结果由 Plugin Manager 返回；只有 `restart-required` 时提示重启 Harness。

设置页在工作台功能已开启且三方市场关闭时，说明改为：网络市场未开放；工作台市场展示本企业上传的工作台，可以直接安装；已安装里保留本机已安装和本地开发的工作台。三方市场打开时，保留现有公开市场说明，并补充可在「来自企业」安装本企业上传的工作台。

文案走工作台 locale，中英文同时提供；实现时须补齐当前工作台页面仍存在的硬编码中文。加载中、失败重试、空目录和无权限都要有文案。读取失败保留页签，列表区显示失败和重试，不能显示成空市场，也不能回退到公开目录或上一租户缓存。空目录说明企业还没有可展示的工作台，请联系管理员上传。深色主题下页签、卡片和校验结果可见。

服务端接口尚未部署、返回 404 或明确表示能力不可用时，显示「企业工作台服务暂不可用」，并保留「已安装」和本机开发入口。该状态不是空目录，不回退到公开市场，也不影响用户使用已安装工作台。

市场内搜索只过滤已经取回的 `display_name`、`description`、`package_name` 和身份文本。服务端列表契约没有查询参数，客户端不添加 `q`。

## 9. 原包核对

核对是 P1 的用户主动操作，由持有 Broker 响应的一侧完成。按钮文案为「核对原包」，不能写成「下载」或暗示文件会保存。顺序固定：

1. 详情里读取 `artifact_url`、`sha256`、`size_bytes`，并按第 6.2 节校验路径与 ID。
2. 核对本机临时目录可写且剩余空间足够，再用同一个 DSH access token 发起请求。请求设置超时并支持用户取消。HTTP 不成功时按 JSON 错误处理，不把错误页当压缩包。禁止跨域重定向，认证头不随重定向转发。
3. 响应流式写入仅属于本次操作的临时文件，同时累计长度并计算 SHA-256；不得把完整包体载入主进程或渲染进程内存。实际字节数不得超过详情 `size_bytes` 或 512 MiB，超出后立即中止并删除临时文件。
4. 下载完成后，实际字节数等于 `size_bytes`。原始字节的 SHA-256 为 64 位小写十六进制，并与详情 `sha256`、以及去掉双引号后的 `ETag` 一致。`Content-Type` 和 `Content-Disposition` 文件名不能代替摘要。
5. 任一核对失败、取消、超时、账号或租户已变、详情版本已变，都删除临时文件。版本变化时先重新取详情，再决定是否重新核对。不保留损坏文件，不写入工作台安装目录。

成功时界面说明「原包完整性核对通过」。随后立即删除临时文件。安装会另行下载并在装入 generation 后删除临时包。进程异常退出后，下次启动清理归属于企业工作台核对、且未被当前操作占用的残留临时文件。

渲染进程只收到核对结果：成功、失败阶段和可展示的错误。不接收包体，不得到可再提交给本地安装的路径。

## 10. 失败、会话与租户

| 情况 | 处理 |
| --- | --- |
| 身份过期、无权限、网络失败 | 清掉当前列表、详情和临时文件，沿用现有登录流程。不回退到其他租户缓存 |
| 接口未部署或能力不可用 | 显示「企业工作台服务暂不可用」，保留已安装和本机开发入口 |
| 信封不合法或分页结构不合法 | 整次读取失败，显示重试 |
| 单条缺少身份或当前版本 | 跳过该条；其余合法条目照常展示 |
| 工作台不存在或当前版本已切换 | 重新拉列表和详情，停止使用旧 `artifact_url` |
| 原包缺失、长度或摘要不符 | 丢弃字节，提示核对失败，保留不含 token 的诊断 |
| 核对过程中账号变化 | 丢弃字节，不把结果写给新账号 |

企业插件市场用账号 epoch 和 `base|tenant|user` 丢弃过期响应。企业工作台目录、详情和核对使用同一套隔离：在途响应若身份已变，按失败结束，不合并进新列表。

退出登录后立即去掉企业目录。本机「已开启工作台」偏好保留。下次登录成功后再按新租户请求。

## 11. 技术约束与实现接缝

凭据路径与企业插件一致，不新建第二套登录。

- 主进程 `parseMarketRequest` 增加三条路径。列表只允许查询参数 `page`、`size`。详情和制品不允许查询串，不允许 body。制品路径形态为 `workbenches/{32 位十六进制}/versions/{32 位十六进制}/artifact`，按二进制响应处理。除此之外的市场路径仍拒绝。
- 企业插件继续通过 `accountController.marketRequest` 调用 Broker。新增本机路由供工作台读取目录、详情和核对。具体路由命名在技术设计中确定；工作台插件使用现有同源 `fetch`，不互相 import 对方的 client。
- 工作台客户端把企业目录放在独立列表中，不写入 `remoteCatalog`，因此不能走到 `installFromMarket`。企业 `id` 也不写入收藏或 `market-installs.json`。
- `allow_third_party_workbenches` 继续只传给现有的公开 catalog 与 `authorizeWorkbenchMarketInstall`。企业目录请求不读这个布尔值做放行。
- 日志保留阶段、工作台 `id`、版本 `id` 和失败原因。不记录 token、完整制品或签名材料。

`scripts/mock-bisheng-enterprise.mjs` 需要能返回两份样例：一份 `identity_kind=repository`，一份 `legacy` 且 `workbench_key=null`。制品响应使用契约中的 `Content-Type`、`Content-Disposition`、`ETag` 和 `Cache-Control`。Mock 同时覆盖空列表、错误信封、长度或摘要不符，以及切换租户后旧响应不得写回。

## 12. 验收

目录：

- 三方市场关闭、企业登录有效、用户已开启工作台时，能看到企业上传的条目。公开 catalog 不被请求。
- 同一状态下，本机开发的工作台仍可安装、打开和卸载；`market-install` 被拒绝。
- 三方市场打开时，公开市场的安装、更新、收藏和投稿保持可用；企业条目单独展示，并可以直接安装。
- 仓库身份与旧身份都能展示。旧包不显示 `workbench_key`。两类企业包在原包可核对时都可以安装。
- 空目录、加载失败、单条坏数据和整页失败的文案彼此可区分。失败可以重试，重试不会改用公开目录。
- 服务端接口返回 404 或尚未部署时显示「企业工作台服务暂不可用」，「已安装」和本机开发入口仍可用。
- 某页包含非法条目时按原始条目数推进分页，合法条目仍可展示，不重复请求同一页。

核对：

- 下载字节数和 SHA-256 与详情一致，并与去引号后的 `ETag` 一致。
- 512 MiB 以上、磁盘不足、取消、超时、损坏、缺失、HTTP 错误页和核对中途切换版本时不保留文件。
- 核对过程流式写临时文件，不把完整包体交给渲染进程或一次性载入主进程内存；成功后同样删除文件。
- 核对成功不产生 `market-installs.json` 记录，不调用工作台 generation 安装，本地安装选择器里也没有这份临时文件。

会话：

- 请求只带 DSH access token，不带租户选择头。
- 切换 BiSheng 地址、账号或租户后重新请求，不复用旧目录、详情或下载字节。在途响应不能落到新身份。
- 退出登录后企业目录消失。已安装工作台、会话、笔记和收藏仍在。

回归：

- 「来自企业」插件的目录、安装、更新、启用、停用和卸载保持原有市场流程。分发改为在线席位和发布快照。
- `allow_third_party_plugins` 的行为不变。
- 关闭工作台功能后，左侧入口消失，企业目录不再展示；再次打开后按当前租户重新读取。
