# Work 企业工具与技能

登录毕昇一次，Work 使用当前账号调用企业工具。凭据交换与刷新由桌面宿主处理；模型接收工具目录和结果。

## 合入基线

2026-10-22：平台 `feat/bisheng-work-120-main@a15826aeb`；桌面 `V1.2.0@56dcf4b`；安装的 Harness `0.2.0-rc.2`，Electron `43.0.0`。本次整合 3007 已验收能力与最新主线。

## 运行逻辑

- 工具目录与调用使用 `/api/v1/dsh/work/mcp`，按当前租户、用户 use 权限和账号联网搜索设置过滤；每次调用重新校验。复用平台 ToolExecutor 与审计。
- Harness 原生 MCP 工具注册和审批承接实际执行；主 Work 任务可调用，企业工具对子任务保持隔离。账号变化取消在途调用并清理旧工具。
- 企业技能复用 V1.2.0 已有的单一 Skill provider、可读名称、完整 ZIP 文件包与按账号隔离的版本缓存。技能内容、脚本和二进制附件按完整内容哈希校验。
- 技能每次加载，包括命中本地缓存时，通过宿主固定 `/dsh/work/skills/{id}/dependencies` 接口重新检查版本、资源权限与工具依赖。依赖映射到 `mcp__bisheng__bisheng_tool_<id>`，沿用原生工具策略。
- 网页侧的工具与技能中心、输入框二级菜单和行内引用由平台前端负责；桌面嵌入同一页面。技能选择继续留在当前 Work 任务。

## 技能声明工具依赖

```yaml
metadata:
  bisheng-work:
    tool_ids: [7]
```

工具 ID 指向所在企业的真实工具记录。管理员负责工具配置；技能加载时校验当前用户的可用性。联网搜索关闭后，输入菜单、MCP 目录和调用执行器均执行账号设置。知识库检索继续按知识空间权限运行。
